# 自平衡小车（STM32F103C8T6 / 裸机 / 200Hz 直立环）

一个**两轮自平衡小车**的固件工程：STM32F103C8T6（蓝丸板，实际是 CKS32F103 克隆片）+ MPU6050 + L298N，
PlatformIO + STM32Cube HAL，**无 RTOS、无第三方库、无动态内存**。

工程的重点不在"能跑一个 PID"，而在于**把一台会自己摔倒的机器安全地调起来**：
先只算不输出（DRY_RUN），在串口上核对符号和量级，确认无误后才给电机上电。

> 当前状态（如实说）：
> - 已完成并**构建通过**：BSP（时钟/串口/I2C/MPU/TIM）、互补滤波姿态、通用 PID、
>   200Hz 直立 + 转向控制环、倾倒锁存、软启动、遥测。
> - **未上板验证**：所有控制参数（Kp/Ki/Kd）、所有符号方向、电机实际响应、整车能否立住。
>   本文档里的参数是**起步值**，不是整定结果。上板流程见 [§7](#7-dry_run--上板-分步验收)。

---

## 1. 项目定位

- **是什么**：两轮差速平衡车的控制固件。MPU6050 出姿态 → 200Hz 直立 PD + 转向 P → L298N 双路 PWM。
- **不是什么**：没有编码器，所以**没有速度环、没有位置环**，车会缓慢漂移（详见 [§8 已知限制](#8-已知限制)）；
  没有遥控/蓝牙输入，转向目标暂时固定在宏里。
- **给谁看**：想搞清楚"平衡车到底怎么立起来"的人。代码里所有注释都在讲**为什么**这么写，
  以及**踩过的坑**（静默失败的那几种）。

## 2. 硬件清单

| 器件 | 型号 / 规格 | 说明 |
|------|------------|------|
| 主控 | STM32F103C8T6 最小系统板（蓝丸） | 实际芯片为 CKS32F103 克隆片，SWD IDCODE = `0x2ba01477` |
| 姿态传感器 | MPU6050 模块（GY-521） | I2C，7 位地址 `0x68`（AD0 接 GND） |
| 电机驱动 | L298N 模块 | 双路 H 桥，支持 2 路 PWM 调速 |
| 电机 | 直流减速电机 ×2（带轮） | 左右各一，差速转向 |
| 电源 | 2S 锂电（7.4V）或 6×AA | L298N 的 `+12V` 接电池，板子 5V 由 L298N 的 5V 输出供 |
| 调试 | ST-Link V2（SWD 四线） | 只用 3.3V / GND / SWDIO / SWCLK |

**L298N 供电注意**：模块自带 5V 稳压输出（板上有跳线帽时），可以直接给蓝丸的 5V 脚供电；
但如果电池电压 >12V 必须拔掉那个跳线帽，否则会烧稳压块。**电机电源和逻辑电源必须共地**，这是最常见的不转原因。

## 3. 接线表（与代码逐一对应）

### 3.1 STM32 ↔ L298N（电机）

| STM32 引脚 | 定时器/功能 | L298N 引脚 | 代码里的名字 | 说明 |
|-----------|------------|-----------|-------------|------|
| **PA0** | TIM2_CH1（PWM，20kHz） | ENA | `BSP_TIM_PWM_PERIOD` 通道 1 | 左轮调速 |
| **PA1** | TIM2_CH2（PWM，20kHz） | ENB | 通道 2 | 右轮调速 |
| **PB0** | GPIO 推挽输出 | IN1 | `MOTOR_LEFT_IN1_PIN` | 左轮方向 1 |
| **PB1** | GPIO 推挽输出 | IN2 | `MOTOR_LEFT_IN2_PIN` | 左轮方向 2 |
| **PB8** | GPIO 推挽输出 | IN3 | `MOTOR_RIGHT_IN1_PIN` | 右轮方向 1 |
| **PB9** | GPIO 推挽输出 | IN4 | `MOTOR_RIGHT_IN2_PIN` | 右轮方向 2 |

> ⚠️ **必须拔掉 L298N 上 ENA / ENB 的跳线帽**。跳线帽把 EN 直接短到 5V，
> 你的 PWM 会和 5V 硬顶，表现为"轮子要么全速要么不转，调速完全无效"。

**方向约定**（`Motor_SetSigned()`）：占空比为正 = 前进，为负 = 后退，0 = 松开（IN1=IN2=0，自由滑行）。

### 3.2 STM32 ↔ MPU6050（I2C）

| STM32 引脚 | 功能 | MPU6050 引脚 | 说明 |
|-----------|------|-------------|------|
| **PB6** | I2C1_SCL（复用开漏） | SCL | 100kHz，模块自带上拉 |
| **PB7** | I2C1_SDA（复用开漏） | SDA | |
| 3.3V | 电源 | VCC | 模块自带 LDO，接 3.3V 或 5V 都可 |

| — | — | INT | 不接（本工程用定时器采样，不走数据就绪中断） |

### 5.2 节拍与优先级

| 项 | 值 | 算式 |
|----|----|------|
| 控制周期 | **5.000 ms**（200 Hz） | TIM4：PSC=71 → 1MHz；ARR=4999 → 5000 × 1µs = 5ms |
| PWM 载波 | **20 kHz** | TIM2：PSC=0 → 72MHz；ARR=3599 → 72MHz / 3600 |
| 占空比分辨率 | 1/3600 ≈ 0.028% | CCR ∈ [0, 3600] |
| SysTick 优先级 | **0（最高）** | 见下方"为什么" |
| TIM4 优先级 | 1 | |
| 中断占用 | 约 1.5~2 ms / 5 ms（30~40%） | 大头是 I2C 14 字节阻塞读 |

**为什么 SysTick 要提到最高优先级**：HAL 的 I2C 超时靠 `HAL_GetTick()` 计数，而 `HAL_Init()` 默认把 SysTick
设成最低优先级 15。如果 TIM4 优先级比 SysTick 高，一旦控制拍里的 I2C 卡住，SysTick 就进不来 →
tick 不涨 → 超时永不触发 → **卡死在中断里，整机假死，串口也停了**。这个坑不修，现场表现是"偶尔死机，查不出来"。

**为什么 dt 用常数 0.005f 而不是 `HAL_GetTick()` 差值**：
5ms 里只可能跨 0 或 1 个 1ms 的 SysTick，差值量化误差最大 100%（4ms 或 5ms），拿它积分/微分等于每拍给控制量
加一次随机扰动。定时器的 5ms 是硬件精确的。`HAL_GetTick()` 只用来数"漏了几拍"（`OV` 计数），不参与运算 ——
顺带把"dt=0 除零"从根上消灭了。

## 6. PID 参数含义与整定顺序

### 6.1 量纲（先看懂这个，再看数字）

输出 = **CCR**，满量程 3600。所以：

| 参数 | 单位 | 直白解释 |
|------|------|---------|
| `BAL_ANGLE_KP = 45` | CCR / 度 | 车歪 1°，就给 45/3600 ≈ 1.25% 的占空比 |
| `BAL_ANGLE_KD = 1.5` | CCR / (°/s) | 车以 100°/s 倒下去，D 项额外加 150 CCR 往回拉 |
| `BAL_ANGLE_KI = 0` | CCR / (度·秒) | **保持 0**，原因见下 |
| `BAL_STEER_KP = 8` | CCR / (°/s) | 车以 30°/s 自己在转，就给 240 CCR 的左右差速去顶回来 |

**为什么直立环不留 Ki**：理论上 Ki 能消掉"稳态倾斜"，但两轮平衡车的"稳态倾斜"在物理上等于
"持续加速"。没有编码器时，积分会让车为了修正那 0.5° 一路加速冲出去，而且收不回来。
如果你以后加了编码器（有了速度环），应该把积分放在**速度环**上，而不是角度环。

**抗饱和用的是 clamp（积分钳位 + 条件积分）**，不是 back-calculation：
后者要多一个"回算时间常数 Tt"，本质上是第二个调不出来的增益，对新手是纯粹的坑。
代码里的实现是：积分项先钳到 `integ_max`（直立环给 ±900，即 1/4 满量程），
并且"输出已经顶到限幅、误差还在往同向推"的那一拍**不累积积分**。

### 6.2 整定顺序（严格按这个顺序，别跳）

> 全程 `CAR_DRY_RUN = 1`（默认值）。所有调整都在串口上先看数，不要上电。

| 步骤 | 做什么 | 怎么判断对了 |
|------|--------|-------------|
| **0. 校零** | 上电时车必须**完全静止** | `[cal] done`；静止时 `P` 稳定在 ±0.5° 内，`GY` ±1°/s 内 |
| **1. 核对符号** | 手扶车体前倾/后仰，看 `L/R` 的正负 | 前倾（P 变负）→ `L/R` 变**正**；后仰（P 变正）→ `L/R` 变**负**。反了就 `BAL_PITCH_DIR = -1.0f` |
| **2. 只开 P** | `Kp = 25`，`Ki = Kd = 0` | 上板（手扶）：车能明显出力去追，但会左右来回摆 → 逐步加到开始"抖"（约 45~70），**退回 60%** |
| **3. 加 D** | `Kd = 0.5` 起，每次 ×1.5 | 摆动被压住、声音变"紧"。加到出现**高频啸叫/电流声**就是过头了，**退回 70%** |
| **4. 转向 P** | `BAL_STEER_KP = 8`，`BAL_STEER_TARGET_DPS = 0` | 手推车尾让它原地转，它应该"抗拒"旋转；能站住但会慢慢回到某个朝向 → 正常（没有偏航基准） |
| **5. Ki** | 一般**不加**。真要加从 0.05 起，且必须同时有编码器速度环 | 不加就是对的 |

**量级自检**（DRY_RUN 下很好用）：把车倾斜 **5°** 并保持不动，`A` 应该≈ `45 × 5 = 225`（±10%），
`L/R` ≈ ±225（斜坡满 100% 后）。如果倾斜 5° 就接近 ±3000，说明 Kp 大了 10 倍，先别上电。

### 6.3 所有可调参数（都在 `include/control/balance.h`）

| 宏 | 默认 | 作用 |
|----|------|------|
| `CAR_DRY_RUN` | `1` | 1 = 只算不输出；0 = 真驱动 |
| `BAL_ANGLE_KP` | `45.0f` | 直立环 P |
| `BAL_ANGLE_KI` | `0.0f` | 直立环 I（建议保持 0） |
| `BAL_ANGLE_KD` | `1.5f` | 直立环 D（作用在陀螺角速度上） |
| `BAL_STEER_KP` | `8.0f` | 转向环 P |
| `BAL_STEER_LIMIT` | `600.0f` | 转向最大差速 |
| `BAL_STEER_TARGET_DPS` | `0.0f` | 转向目标角速度（调试可给 ±30） |
| `BAL_TILT_LIMIT_DEG` | `45.0f` | 倾倒判定阈值（锁存停机） |
| `BAL_UPRIGHT_ARM_DEG` | `10.0f` | 起控角（扶正到这个范围内才允许出力） |
| `BAL_SOFT_START_MS` | `1200` | 软启动时长 |

## 7. DRY_RUN → 上板 分步验收

**每一步都要过了才做下一步。** 全程车要放在桌面上、手能立刻扶到。

### 阶段 A：只算不输出（`CAR_DRY_RUN = 1`，默认）

| # | 操作 | 期望现象 | 不对怎么办 |
|---|------|---------|-----------|
| A1 | `pio run -t upload`，串口 115200 | `[init]` 全 OK，`[cal] done`，`[mode] CAR_DRY_RUN=1` | 见 [§9 排查表](#9-故障排查表) |
| A2 | 车放正（±10° 内） | 状态 `WAIT` → `RUN`；`RMP` 1.2 秒内从 0 涨到 100 | 一直 `WAIT`：pitch 超 10° 或 MPU 没数据 |
| A3 | 前倾/后仰，看 `P` 和 `L/R` | 前倾 P 负 → L/R 正（轮子会往前追） | 反了 → `BAL_PITCH_DIR = -1.0f` |
| A4 | 倾斜 5° 不动，看量级 | `A ≈ ±225`，`L/R ≈ ±225` | 差 10 倍 → 检查 Kp 单位理解，别上电 |
| A5 | 推车尾让它左转，看 `S` 和 `L/R` | `S` 变负，`L` 比 `R` 大（准备右转纠正） | 反了 → `BAL_YAW_DIR = -1.0f` |
| A6 | **把车倒到 >45°** | 立刻 `FAULT` + `[fault] TILT...`；`L/R = 0`；扶正也不恢复 | 不锁存就是安全逻辑坏了，别上电 |
| A7 | 断电重启 | 恢复 `WAIT` → `RUN` | |

### 阶段 B：轮子离地转起来（`CAR_DRY_RUN = 0`）

| # | 操作 | 期望现象 |
|---|------|---------|
| B1 | **把车架空**（轮子悬空），改 `CAR_DRY_RUN 0`，烧录 | 串口打印 `[mode] CAR_DRY_RUN=0 真实驱动电机！先把车架空再上电` |
| B2 | 上电，扶正 | 轮子按 `L/R` 的符号转；前倾 → 轮子往前；后倾 → 轮子往后 |
| B3 | 听声音 / 摸电机 | 方向对、转速随倾角变化 = 通过。方向反了回阶段 A2 |
| B4 | 手扶倾斜超过 45° | 轮子**立刻停**（`FAULT`），不会乱转 |

### 阶段 C：落地

| # | 操作 | 期望现象 |
|---|------|---------|
| C1 | 把 `BAL_ANGLE_KP` 临时降到 **25**，落地，一只手扶住车顶 | 能感觉到它在"抢"，但立不住 |
| C2 | 慢慢松手 | 大概率会前后摆 → 回到阶段 A 的思路，加 `Kd` |
| C3 | `Kd` 每次 ×1.5，直到摆动被压住；出现高频抖动就退回 70% | 能立 3~5 秒 |
| C4 | 微调 `Kp` ±20% | 立得更稳 |
| C5 | 加转向 | `BAL_STEER_KP` 从小到大，车应该"抗拒"被转动 |

> **安全底线**：任何时候出现"越倒越快"的正反馈、或者轮子满速自转不停，**先拔电池**，再回串口看数。
> 不要靠改代码去救一个已经在满速跑的车。

## 8. 已知限制

如实列出，这些不是 bug，是**当前硬件/结构决定的**：

1. **没有编码器 → 没有速度环，也没有位置环。**
   直接后果：车能"立住"，但会**缓慢漂移**（往一个方向越走越快），
   并且**无法自动回到原点**。想解决必须加编码器（或至少加一个速度估计），
   然后把 PID 改成串级：外环速度/位置 → 内环角度。
2. **没有转向输入。** 目标偏航角速度写死在 `BAL_STEER_TARGET_DPS`（默认 0）。
   没有遥控/蓝牙/串口接收（USART1 只配了 TX），所以转弯只能靠改宏。
3. **偏航没有绝对基准。** 只有陀螺积分，没有磁力计，`yaw` 会漂；
   所以转向环只能用**角速度**做阻尼，不能用"转到某个朝向"。
4. **占空比 → 转速是开环的。** 电池电压往下掉、地面摩擦变化、L298N 上约 2V 的压降，
   都会让"同样的 CCR 得到不同的转速"。这也是为什么 Kp 在电池满电和快没电时手感不一样。
5. **I2C 采样是定时的，不是"数据就绪"触发的。** 没用 MPU6050 的 INT 引脚，
   每一拍读到的是"最近一次转换结果"，年龄 0~5ms 抖动。
6. **控制拍里 I2C 是阻塞的**，约 1.5~2ms / 5ms（30~40% CPU）。
   再往这一拍里加任何重活（比如 OLED 刷新、串口打印）都会直接把节拍撑爆。
7. **没有看门狗（IWDG）。** 如果控制拍卡死，主循环会一起停（`OV` 也不再涨），
   只能靠人看出来。要加的话在 `main` 里初始化 IWDG 并在主循环喂狗。
8. **`bsp_oled.c` 目前是死代码**（预留了驱动，没接到任何地方）。
9. **主循环 printf 是阻塞的**，一行约 10ms @115200，会轻微拉长遥测周期（不影响控制）。

## 9. 故障排查表

| 现象 | 最可能的原因 | 处理 |
|------|-------------|------|
| **`[init] mpu : FAIL`，WHO_AM_I 读得到但值不对** | ① AD0 悬空 → 地址在 0x68/0x69 之间跳；② 不是 MPU6050（MPU6500 = `0x70`，MPU9250 = `0x71`）；③ 模块虚焊 | AD0 明确接 GND；用 `BspMpu_Init` 里读到的 `who` 值对照芯片型号；换模块 |
| **`[init] i2c : FAIL` / 之后一直 `HAL_BUSY`** | 总线被拽住（SDA 一直低）。常见于上次复位时从机正传到一半 | `BspI2c_Init` 里已内置解锁：9 个 SCL 脉冲 + STOP。还不行就查**上拉电阻**（模块自带 4.7k，两模块并联会变 2.35k，仍可用）、**线长**（>20cm 容易出问题）、**共地** |
| **I2C 偶发失败、`IMU` 计数一直涨** | 电机换向的电流尖峰干扰了 I2C | SDA/SCL 远离电机线；加 100nF 去耦；必要时把 I2C 降到 50kHz |
| **串口浮点全空白（`float=` 后面没东西）** | `platformio.ini` 里的 `-Wl,-u,_printf_float` 没生效（newlib-nano 默认砍掉浮点格式化） | 检查 `build_flags` 那三行，注意**必须是 `-Wl,-u,_printf_float` 连写**，`-u _printf_float` 会被拆成两个 flag |
| **串口全是乱码 / 一个字都没有** | 波特率不对 / 没共地 / TX 接错脚 | 115200 8N1；USB-TTL 的 RXD 接 PA9；GND 必须接 |
| **轮子不转，但串口一切正常** | ① **L298N 的 ENA/ENB 跳线帽没拔**（PWM 被 5V 顶死）；② 电机电源没接 / 没共地；③ `CAR_DRY_RUN` 还是 1 | 拔跳线帽；量 L298N 的 +12V 和 GND；看启动时打印的 `[mode]` |
| **轮子只朝一个方向转，反向不动** | L298N 某一路 IN 脚没接好 / 该路半桥坏 | 交换 IN1/IN2 试；换一路驱动 |
| **车越倒越快（正反馈）** | 符号错了 | `BAL_PITCH_DIR = -1.0f`（不要靠改接线，那样串口打印的正负也会跟着拧巴） |
| **能立但一直高频抖 / 电机啸叫** | `Kd` 太大，或 MPU 没固定牢（机械共振） | `Kd` 退回 70%；MPU 用硬质双面胶/螺丝固定，别用海绵 |
| **上电后一直 `WAIT`** | pitch 超过 `BAL_UPRIGHT_ARM_DEG`（10°），或 MPU 没数据 | 扶正；看 `P` 有没有数 |
| **一使能就窜出去** | 软启动被跳过（状态机直接进 `RUNNING`），或 `integ_max` 里攒了旧积分 | 每次进 `RUNNING` 前都会 `Pid_Reset`；检查是不是 `Kp` 大了一个数量级 |
| **`OV` 计数一直涨** | 控制拍超时（I2C 变慢、被更高优先级中断打断） | 检查 I2C 速率和上拉；别在控制拍里加活 |
| **L298N / 电机发热明显，有轻微啸叫** | 20kHz 载波下 L298N（达林顿 BJT 桥）的开关损耗比低速 PWM 大 | 优先**换驱动芯片**（TB6612 / DRV8871 / DRV8833），别改 PWM 频率：改 ARR 要连带改 `BSP_TIM_PWM_PERIOD`、`BAL_MAX_DUTY`、`BAL_STEER_LIMIT` 和 Kp/Kd 的量纲（它们全是"CCR 每度"），一个不同步整套参数就作废 |
| **烧录失败 `Error: init mode failed`** | 克隆片 IDCODE 不对 / ST-Link 接线 / BOOT0 | `platformio.ini` 里的 `set CPUTAPID 0x2ba01477` 必须保留；SWDIO/SWCLK 别接反；BOOT0 拉低后复位 |

## 11. 几个"为什么这么写"（踩过的坑）

1. **PID 用位置式**：增量式丢一拍就永久偏一个量；位置式每拍重算，抗丢拍。
2. **微分作用在测量值上**：设定值一跳，误差微分会给一个尖峰把车打抖。测量值微分没这个问题。
3. **D 项直接用陀螺，不对融合后的角度做差分**：互补滤波里那 2% 的加速度修正本身是有噪声的，
   拿它去微分等于给 D 项加噪声。陀螺本来就是角速度，白送。
4. **`dt` 用常数**：见 [§5.2](#52-节拍与优先级)。`HAL_GetTick()` 只数丢拍，不参与运算。
5. **SysTick 提到最高优先级**：否则中断里的 HAL I2C 超时永远不触发，整机假死。
6. **主循环绝不碰 MPU**：I2C1 是共享资源，中断在做 14 字节突发读，主循环插进去两边都拿错数据，
   症状是"偶发角度跳变"，极难查。主循环只读 `Balance_GetTelemetry()` 的快照（内部短暂关中断保证不撕裂）。
7. **`Motor_SetSigned` 而不是复用 `Motor_SetSpeed`**：后者吃 `uint16_t`，负值传进去会变成 6 万多，
   直接满速反转。这是"PID 输出接无符号接口"最经典的翻车点。
8. **倾倒锁存，不自动恢复**：车倒了以后自己爬起来重新满速，比停下来更危险。必须断电重启（或显式调 `Balance_ClearFault()`）。
9. **起控要"扶正"才允许**：否则车侧躺在地上也能进 `RUNNING`，第一拍就是一个满占空比。
10. **软启动**：从 0 线性拉满 1.2s，避免"刚使能就满占空比"把车弹出去。

## 12. 后续想做的事（按优先级）

1. 加编码器（TIM3/TIM4 编码器模式）→ 速度环 → 串级 PID → 能自动保持位置。
2. 加蓝牙/串口接收 → 遥控转向（`BAL_STEER_TARGET_DPS` 改成变量）。
3. MPU6050 的 INT 引脚接 EXTI → 数据就绪触发采样，把控制拍里那 1.5ms 阻塞 I2C 去掉。
4. 加 IWDG，卡死自动复位。
5. 电池电压检测（ADC）→ 电压补偿 PWM，让不同电量下手感一致。
